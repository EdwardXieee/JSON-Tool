使用帮助

我应该用哪个功能？

最常用的是格式化和对比，其他工具只在遇到对应问题时使用。

想把 JSON 排版整齐

使用“格式化 / 压缩”，粘贴后点击格式化。

想比较两份返回数据

使用“JSON 对比”，左边放旧数据，右边放新数据。

日志里夹着 JSON

使用“日志提取”，它会自动找到完整的对象和数组。

大 JSON 里只想找几个值

使用“查询 / 校验”中的 JSONPath，不需要手工逐层查找。

高级对比设置

默认对比已经适合大多数场景。只有结果里出现大量“看起来不同、业务上其实一样”的内容时，再启用下面的规则。

忽略数组顺序

数组只是前后顺序变化时不报差异。适合无固定排序的接口列表。

[1, 2] 等同于 [2, 1]
宽松类型

数字和布尔值被转成字符串时仍视为相同。

"1" 等同于 1 "true" 等同于 true
缺失等同 null

接口省略空字段时不报差异。

{} 等同于 {"note": null}
数组业务键

填写数组元素的唯一字段，例如 id。即使订单换了位置，也会按相同 id 对比。

填写：id 也支持：meta.orderId
忽略路径

忽略每次都会变化的字段，一行写一个路径。

$.timestamp $.items[*].updateTime

什么是变更补丁？

变更补丁也叫 JSON Patch，它不是给人阅读的对比报告，而是给程序执行的修改指令。普通查看差异时不需要它。

[{"op":"replace","path":"/status","value":"SUCCESS"}]
上面的意思是：把 status 字段改成 SUCCESS。补丁始终严格描述 JSON A → JSON B，不受“忽略路径”等高级对比规则影响。

普通日志和 NDJSON 有什么区别？

普通日志

JSON 前后还有时间、级别或说明文字，选择“从普通日志提取 JSON”。

10:30 INFO response={"ok":true}
NDJSON / JSONL

一行就是一份完整 JSON，选择“解析每行一个 JSON”。

{"id":1} {"id":2}
“分别格式化”便于逐段阅读；“合并为数组”会把选中的多份 JSON 变成一份标准 JSON 数组。

JSONPath 怎么用？

把 JSONPath 理解成 JSON 的“查找地址”。左侧放完整 JSON，右侧写要找的位置，然后点击查询。

全部数据
$
所有层级中的 id
$..id
items 数组中的每一项
$.items[*]
筛选金额大于 100 的项
$.items[?(@.amount > 100)]

JSON Schema 怎么用？

JSON 是待检查的数据，Schema 是检查规则。它适合接口测试或检查配置文件，不需要时可以忽略。

在左侧粘贴需要检查的 JSON。
在 Schema 输入框粘贴规则，或点击“填入可运行示例”。
点击“校验”；valid 为 true 表示通过，errors 会列出不符合规则的位置和原因。
{ "type": "object", "required": ["id"], "properties": { "id": {"type": "string"} } }
